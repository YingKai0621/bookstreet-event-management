## 1. Purpose

This overlay defines the exact Sprint 09 physical persistence boundary for Heritage public content. It
translates the approved domain into one PostgreSQL table for the assigned migration owner.

The design intentionally keeps Heritage independent from General Feedback, Event, Activity, Location,
Map, QR persistence, analytics, and Admin management.

This overlay must be reviewed together with the Sprint 09 baseline, Use Case Specifications, API Contract,
implementation plan, and documentation audit before a Flyway migration is created.

## 2. Source-of-truth alignment

The overlay follows these current decisions:

- Heritage is supporting public content under `UC-G01` and `UC-O09`
- verified Organizers manage one shared Heritage collection
- Admin has no Heritage management API or UI in Sprint 09
- General Feedback targets remain only `BOOK_STREET` and `EVENT`
- Heritage has no relationship with `general_feedbacks`
- public reads expose only `PUBLISHED` content
- lifecycle statuses are exactly `DRAFT`, `PUBLISHED`, and `ARCHIVED`
- only a never-published draft may be hard-deleted
- `publicCode` is the stable immutable public identity
- Heritage QR is neither displayed nor persisted

The existing target Physical ERD already proposes the minimal Heritage field set. This overlay locks the
constraints, indexes, lifecycle invariants, and migration behavior that the target diagram leaves open.

## 3. Physical table

### 3.1 Table name

`heritage_contents`

### 3.2 Table responsibility

The table stores durable Heritage content and its publication lifecycle. It does not store per-Organizer
ownership, review assignments, Feedback references, map coordinates, QR records, analytics, translations,
or uploaded image bytes.

### 3.3 Physical columns

| Column | Physical type | Null | Default | Purpose |
| --- | --- | --- | --- | --- |
| `heritage_content_id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | No | Identity | Internal primary key for persistence and Organizer operations |
| `public_code` | `VARCHAR(100)` | No | None | Stable immutable public identity stored in canonical uppercase form |
| `title` | `VARCHAR(200)` | No | None | Normalized plain-text public title |
| `summary` | `TEXT` | Yes | None | Optional normalized plain-text short summary |
| `content` | `TEXT` | No | None | Required normalized plain-text Heritage content |
| `image_url` | `TEXT` | Yes | None | Optional HTTP or HTTPS URL, or approved local public asset path |
| `location_text` | `VARCHAR(255)` | Yes | None | Optional display-only location description |
| `status` | `VARCHAR(20)` | No | `'DRAFT'` | Publication lifecycle status |
| `published_at` | `TIMESTAMPTZ` | Yes | None | Time of first publication, preserved after archive and republish |
| `created_at` | `TIMESTAMPTZ` | No | `CURRENT_TIMESTAMP` | Durable creation time |
| `updated_at` | `TIMESTAMPTZ` | No | `CURRENT_TIMESTAMP` | Time of the latest accepted content or lifecycle mutation |

The table adds one active production table. If applied after V14 with no other schema change, the current
30-table baseline becomes 31 active tables.

## 4. Keys and relationships

### 4.1 Primary key

- `pk_heritage_contents` on `heritage_content_id`

### 4.2 Unique public identity

- `uq_heritage_contents_public_code` on `public_code`

The database stores only canonical uppercase `public_code` values and rejects noncanonical values. The
regular unique constraint therefore enforces the approved case-insensitive identity without adding a
redundant functional unique index.

The application generates the code from the normalized title before persistence. The database constraint
remains the final guard against direct or defective writes.

Historical immutability cannot be expressed by a row-level CHECK without a trigger. Sprint 09 therefore
enforces `public_code` immutability through a non-updatable ORM mapping and content-update commands that never
accept the field. The Sprint deliberately avoids an immutability trigger.

### 4.3 Foreign keys

There are no foreign keys in `heritage_contents` for Sprint 09.

In particular, the model does not include:

- `event_id`
- `location_id`
- `created_by_user_id`
- `updated_by_user_id`
- `heritage_content_id` in `general_feedbacks`

The shared Organizer collection has no per-Organizer ownership relationship. The optional
`location_text` value is presentation text and does not create a Location or Map relationship.

## 5. Database constraints

### 5.1 Public-code constraint

Constraint name: `ck_heritage_contents_public_code`

The value must satisfy all of these rules:

- equals its trimmed value
- equals its uppercase value
- has between 3 and 100 characters
- starts with an ASCII letter
- contains only ASCII letters, digits, and single hyphen-separated segments
- has no leading, trailing, or repeated hyphen

The database expression is equivalent to:

```text
public_code = BTRIM(public_code)
AND public_code = UPPER(public_code)
AND CHAR_LENGTH(public_code) BETWEEN 3 AND 100
AND public_code ~ '^[A-Z][A-Z0-9]*(-[A-Z0-9]+)*$'
```

Valid examples include `DS-01`, `LICH-SU-01`, and `HERITAGE2026`. Invalid examples include `ds-01`,
`-DS01`, `DS--01`, `DS-`, and values containing spaces.

### 5.2 Title constraint

Constraint name: `ck_heritage_contents_title`

The value must:

- equal its trimmed value
- contain between 2 and 200 characters

The database expression is equivalent to:

```text
title = BTRIM(title)
AND CHAR_LENGTH(title) BETWEEN 2 AND 200
```

The service normalizes repeated horizontal whitespace. The database guards surrounding whitespace and
length without rewriting content.

### 5.3 Summary constraint

Constraint name: `ck_heritage_contents_summary`

When non-null, the value must:

- equal its trimmed value
- contain between 1 and 1000 characters

Blank optional input is normalized to null before persistence.

The database expression is equivalent to:

```text
summary IS NULL
OR (
    summary = BTRIM(summary)
    AND CHAR_LENGTH(summary) BETWEEN 1 AND 1000
)
```

### 5.4 Content constraint

Constraint name: `ck_heritage_contents_content`

The value must:

- have no leading or trailing whitespace
- contain between 20 and 20000 characters

The database preserves intentional internal whitespace and line breaks. Rendering remains escaped plain
text. The schema does not attempt to sanitize HTML through a fragile database pattern.

The database expression is equivalent to:

```text
content = REGEXP_REPLACE(content, '^[[:space:]]+|[[:space:]]+$', '', 'g')
AND CHAR_LENGTH(content) BETWEEN 20 AND 20000
```

### 5.5 Image URL constraint

Constraint name: `ck_heritage_contents_image_url`

When non-null, the value must:

- equal its trimmed value
- contain between 1 and 2048 characters
- start with `http://`, `https://`, or the approved local prefix `/assets/heritage/`
- reject protocol-relative paths beginning with `//`

The service performs full URI validation. Data URLs, blob URLs, filesystem paths, and raw image bytes are
rejected before persistence.

The database expression is equivalent to:

```text
image_url IS NULL
OR (
    image_url = BTRIM(image_url)
    AND CHAR_LENGTH(image_url) BETWEEN 1 AND 2048
    AND (
        LOWER(image_url) LIKE 'http://%'
        OR LOWER(image_url) LIKE 'https://%'
        OR image_url LIKE '/assets/heritage/%'
    )
)
```

Local paths containing dot segments, backslashes, or control characters are rejected by the service before
persistence. The backend stores the URL but does not fetch the remote resource.

### 5.6 Location-text constraint

Constraint name: `ck_heritage_contents_location_text`

When non-null, the value must:

- equal its trimmed value
- contain between 1 and 255 characters

Blank optional input is normalized to null.

The database expression is equivalent to:

```text
location_text IS NULL
OR (
    location_text = BTRIM(location_text)
    AND CHAR_LENGTH(location_text) BETWEEN 1 AND 255
)
```

### 5.7 Status constraint

Constraint name: `ck_heritage_contents_status`

The only accepted values are:

```text
DRAFT
PUBLISHED
ARCHIVED
```

The database expression is equivalent to:

```text
status IN ('DRAFT', 'PUBLISHED', 'ARCHIVED')
```

The database contains no `HIDDEN`, `DELETED`, `INACTIVE`, or approval-pending status.

### 5.8 Publication-state constraint

Constraint name: `ck_heritage_contents_publication_state`

The legal row states are:

```text
status = DRAFT AND published_at IS NULL
status = PUBLISHED AND published_at IS NOT NULL
status = ARCHIVED AND published_at IS NOT NULL
```

This prevents a published or archived row without first-publication evidence. It also prevents a draft
from carrying a publication timestamp.

The constraint validates row state. Legal transition history remains a service responsibility because a
row-level check cannot determine the previous status without a database trigger. Sprint 09 does not add a
trigger or transition-history table.

### 5.9 Timestamp constraint

Constraint name: `ck_heritage_contents_timestamps`

The value must satisfy:

```text
created_at <= updated_at
AND (
    published_at IS NULL
    OR (
        published_at >= created_at
        AND published_at <= updated_at
    )
)
```

Create, update, publish, archive, and republish services set one operation time for every timestamp changed
by that command. Hibernate callbacks must not silently produce a different lifecycle time.

### 5.10 Concurrency token

`updated_at` is also the optimistic concurrency token for shared Organizer mutations. Organizer detail and
list responses expose it as `updatedAt`. Update, publish, archive, republish, and draft-delete commands carry
the last observed value as `expectedUpdatedAt`.

Every mutation predicate includes the matching `updated_at`. A stale value changes no row and becomes the
stable conflict response defined by the API Contract. This prevents two Organizers from silently overwriting
each other without adding a twelfth column or a generic version-history table.

Every accepted mutation produces an `updated_at` value strictly greater than the prior value at PostgreSQL
timestamp precision. The implementation must not reuse an equal clock value for two accepted versions.

The API Contract must preserve timestamp precision across PostgreSQL, Java `Instant`, JSON, and the browser.
The frontend returns the original `updatedAt` token rather than parsing and reformatting it through a lower
precision browser date object.

## 6. Indexes

### 6.1 Public published-list index

Index name: `idx_heritage_contents_public_published`

```text
(published_at DESC, heritage_content_id DESC)
WHERE status = 'PUBLISHED'
```

This index serves deterministic public ordering and excludes private draft or archived rows.

### 6.2 Organizer queue index

Index name: `idx_heritage_contents_status_updated`

```text
(status, updated_at DESC, heritage_content_id DESC)
```

This index serves the shared Organizer queue with an optional status filter and newest-updated ordering.

### 6.3 Search-index decision

Sprint 09 does not enable `pg_trgm` or create a full-text vector. The expected Heritage collection is small,
and the initial contains-search across `public_code`, `title`, and `location_text` may scan the bounded result
set after approved filters.

The unique public-code constraint already supports canonical exact lookup. A future search extension requires
measured query evidence and a separate approved migration.

## 7. Lifecycle persistence rules

### 7.1 Create draft

Create inserts exactly one row with:

- canonical immutable `public_code`
- validated content fields
- `status = 'DRAFT'`
- `published_at = NULL`
- one operation time for `created_at` and `updated_at`

The create command cannot accept a caller-selected initial status, primary key, or timestamps.

### 7.2 Update content

Content update addresses the internal primary key and changes only approved mutable fields. It cannot change:

- `heritage_content_id`
- `public_code`
- `status`
- `published_at`
- `created_at`

An accepted update sets `updated_at` to the operation time. An update with no supplied mutable field is
rejected rather than treated as success.

The guarded update predicate includes both `heritage_content_id` and `expectedUpdatedAt`. A stale value
returns conflict and preserves the newer row.

### 7.3 Publish

Publish is a guarded transactional command:

- `DRAFT -> PUBLISHED` sets `published_at` and `updated_at` to the operation time
- `ARCHIVED -> PUBLISHED` preserves `published_at` and changes only `status` and `updated_at`
- publishing an already published record or another illegal source state returns a conflict and changes no row

The guarded update includes the expected source status and `expectedUpdatedAt` in its predicate. A zero-row
update is resolved into the stable not-found or conflict result defined by the API Contract.

### 7.4 Archive

Archive is a guarded `PUBLISHED -> ARCHIVED` transactional command. It preserves `public_code`, content,
`published_at`, and `created_at`, then updates `status` and `updated_at`.

The predicate includes `expectedUpdatedAt`. Archiving a draft, already archived record, stale record, or
unknown identity changes no row.

### 7.5 Delete draft

Hard delete uses one guarded delete predicate equivalent to:

```text
heritage_content_id = requested identity
AND status = 'DRAFT'
AND published_at IS NULL
AND updated_at = expectedUpdatedAt
```

Published and archived rows cannot be hard-deleted. The rule is enforced atomically by the repository or
service command rather than by a read-then-delete race.

### 7.6 Public reads

Public list and detail queries always include `status = 'PUBLISHED'` in the database predicate. Filtering only
after loading a broader result is forbidden.

Public detail resolves the canonical `public_code`. Draft, archived, unknown, and malformed values return the
same public not-found behavior without exposing private record existence.

## 8. ORM mapping boundary

The future Heritage entity must follow these mapping rules:

- `@Table(name = "heritage_contents")`
- identity generation compatible with `GENERATED BY DEFAULT AS IDENTITY`
- `HeritageContentStatus` stored with `EnumType.STRING`
- `publicCode` non-null and not updatable after insert
- `updatedAt` returned as the mutation concurrency token with database precision preserved
- database column lengths aligned with this overlay
- nullable optional fields mapped exactly as documented
- timestamps stored as timezone-aware instants
- no entity relationship to User, Event, Location, Feedback, Map, or QR models
- no persistence of frontend-only bilingual, analytics, image metadata, or coordinate fields

The entity owns domain methods or service-controlled commands for content update, publish, archive, and
republish. A generic public status setter is not part of the domain boundary.

### 9.2 Migration contents

The single Heritage migration creates:

- `heritage_contents`
- all named primary, unique, and check constraints in this overlay
- the public partial index
- the Organizer status and ordering index

It does not:

- modify `general_feedbacks`
- add a Feedback foreign key or `HERITAGE` target
- modify another existing table
- insert production or demo Heritage content
- create extensions, triggers, stored procedures, or scheduled jobs
- create Redis keys or application configuration

### 9.3 Verification paths

The migration must pass:

1. a clean migration from V1 through the new version
2. an upgrade from V14 through the new version
3. Hibernate `ddl-auto: validate`
4. PostgreSQL constraint and index inspection
5. focused repository and lifecycle integration tests

No applied migration is edited during verification.

## 10. Required database test matrix

### 10.1 Valid rows

- a minimal valid `DRAFT` row with null optional fields
- a valid `DRAFT` row with every optional field
- a valid `PUBLISHED` row with non-null `published_at`
- a valid `ARCHIVED` row preserving non-null `published_at`
- distinct canonical public codes

### 10.2 Rejected identity and content

- lowercase, padded, too-short, too-long, spaced, repeated-hyphen, or trailing-hyphen public codes
- a case-equivalent or exact duplicate public code
- blank, padded, too-short, or oversized title
- blank or oversized summary
- blank, padded, too-short, or oversized content
- blank, oversized, unsupported-scheme, protocol-relative, data, blob, or filesystem image values
- blank or oversized location text

### 10.3 Rejected lifecycle state

- unsupported status
- `DRAFT` with non-null `published_at`
- `PUBLISHED` with null `published_at`
- `ARCHIVED` with null `published_at`
- `updated_at` earlier than `created_at`
- `published_at` earlier than `created_at` or later than `updated_at`

### 10.4 Guarded command behavior

- publish draft exactly once
- reject publish from published
- archive published exactly once
- reject archive from draft or archived
- republish archived while preserving first `published_at`
- delete a never-published draft
- reject hard delete for published or archived rows
- preserve immutable `public_code` during content update
- reject a stale content update, lifecycle command, or draft delete without overwriting the newer row
- public queries never return draft or archived rows

### 10.5 Regression boundary

- V14 General Feedback constraints remain unchanged
- `general_feedbacks` still has no `heritage_content_id`
- General Feedback still rejects `HERITAGE`
- no existing Event, Booth, Activity, Participant, Payment, Attendance, Reward, Rating, Notification, or
  Feedback table is altered

## 12. Explicit physical exclusions

Sprint 09 does not add these columns or tables:

- English title, summary, content, province, category, period, or highlight fields
- map coordinates or map-area relationship
- image alt text, source, license, binary data, or asset ownership
- QR token, status, image, scan count, or visit record
- view count, engagement count, or analytics aggregate
- created-by, updated-by, reviewer, approver, or owner foreign keys
- version-history, revision, scheduled-publication, translation, comment, or moderation tables
- Heritage Feedback relationship or join table

Any later need for these concepts requires a separate approved baseline and a new migration.

## 13. Overlay audit checklist

Before this overlay can be approved:

- every column must map to the Sprint 09 baseline
- every baseline lifecycle state must satisfy the database constraints
- every forbidden lifecycle state must fail a constraint or guarded command
- `public_code` normalization and uniqueness must agree with the API Contract
- API limits must not exceed database limits
- public and Organizer sort orders must match the declared indexes
- public queries must filter `PUBLISHED` in PostgreSQL
- hard delete must use one guarded predicate
- every Organizer mutation must guard against stale `expectedUpdatedAt`
- no Feedback, Event, Location, User, Map, QR, or analytics relationship may appear
- the candidate migration version must be rechecked before implementation
- clean and V14-upgrade migration tests must exist before merge

## 14. Overlay conclusion

Sprint 09 requires one independent `heritage_contents` table with 11 columns, three lifecycle statuses,
one primary key, one canonical unique public identity, nine named check constraints, and two supporting
indexes.

The design is intentionally small. It supports shared Organizer CRUD and publication, published-only public
reads, stable public URLs without QR presentation, safe draft deletion, and no Heritage Feedback coupling.
