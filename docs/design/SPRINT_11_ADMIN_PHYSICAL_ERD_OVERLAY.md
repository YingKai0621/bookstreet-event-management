# Sprint 11 System Admin Physical ERD Overlay

- Status: `IMPLEMENTED IN V18`
- Prepared date: `2026-11-07`
- Current applied baseline: Flyway `V1` through `V18`
- Implemented migration: `V18__create_admin_audit_log.sql`
- Related Sprint baseline: `docs/sprints/sprint-11.md`
- Reviewed API contract: `docs/api/sprint-11-api-contract.md`

## 1. Purpose

This overlay adds the append-only administrative audit log required by `BR-118` and one `users` column that lets a lock or
password reset end earlier Sessions under `BR-114` and `BR-120`.

Everything else in Sprint 11 uses the existing schema:

| Need | Existing structure |
| --- | --- |
| Account status | `users.status`, already limited to `ACTIVE` and `DISABLED` |
| Roles | `user_roles` and `roles` |
| Organization status | `partner_organizations.status`, already limited to `ACTIVE` and `INACTIVE` |
| Password reset token | `user_tokens`, whose type check already allows `PASSWORD_RESET` |
| Dashboard figures | Aggregates over `users`, `user_roles`, `events`, `booth_assignments`, `booth_payments` and the new audit table |

## 2. New table `admin_audit_logs`

| Column | Type | Null | Purpose |
| --- | --- | --- | --- |
| `audit_log_id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | No | Stable identity |
| `actor_user_id` | `BIGINT` | No | Admin who acted; FK to `users`, `ON DELETE RESTRICT` |
| `action` | `VARCHAR(40)` | No | Closed action value |
| `target_type` | `VARCHAR(30)` | No | Closed target type |
| `target_id` | `BIGINT` | No | ID of the target row |
| `target_label` | `VARCHAR(200)` | No | Username, organization name or Badge name at that moment |
| `reason` | `VARCHAR(500)` | Yes | Required for lock and unlock, null otherwise |
| `details` | `JSONB` | No | Small non-secret facts defined by the API contract |
| `created_at` | `TIMESTAMPTZ` | No | Backend time of the change |

`target_id` has no foreign key because it points to one of three tables. The check on `action` and `target_type` keeps each
action on its correct target type. Users, organizations and Badges have no hard-delete path in this baseline, so targets
stay resolvable. `target_label` also keeps history readable after a rename.

## 3. New column `users.sessions_valid_from`

| Column | Type | Null | Purpose |
| --- | --- | --- | --- |
| `sessions_valid_from` | `TIMESTAMPTZ` | Yes | A Session that signed in before this moment is no longer valid |

- A lock and a successful password reset set it to backend time.
- An unlock does not change it, so Sessions from before the lock do not resume.
- It stays null for existing accounts, so the migration ends no Session.

The authenticated principal stored in the Session gains an `authenticatedAt` value set at sign-in. The enforcement filter
compares the two. A Session whose `authenticatedAt` is missing, created before this change, is treated as older than any
non-null `sessions_valid_from`. This is an application change; Redis stays Session-only.

## 4. Migration

```sql
ALTER TABLE users
    ADD COLUMN sessions_valid_from TIMESTAMPTZ;

CREATE TABLE admin_audit_logs
(
    audit_log_id  BIGINT GENERATED BY DEFAULT AS IDENTITY,
    actor_user_id BIGINT       NOT NULL,
    action        VARCHAR(40)  NOT NULL,
    target_type   VARCHAR(30)  NOT NULL,
    target_id     BIGINT       NOT NULL,
    target_label  VARCHAR(200) NOT NULL,
    reason        VARCHAR(500),
    details       JSONB        NOT NULL DEFAULT '{}'::jsonb,
    created_at    TIMESTAMPTZ  NOT NULL,

    CONSTRAINT pk_admin_audit_logs PRIMARY KEY (audit_log_id),
    CONSTRAINT fk_admin_audit_logs_actor
        FOREIGN KEY (actor_user_id) REFERENCES users (user_id) ON DELETE RESTRICT,
    CONSTRAINT ck_admin_audit_logs_target_positive
        CHECK (target_id > 0),
    CONSTRAINT ck_admin_audit_logs_target_label
        CHECK (BTRIM(target_label) <> ''),
    CONSTRAINT ck_admin_audit_logs_details_object
        CHECK (jsonb_typeof(details) = 'object'),
    CONSTRAINT ck_admin_audit_logs_action_target
        CHECK (
            (target_type = 'USER' AND action IN (
                'USER_CREATED', 'USER_UPDATED', 'USER_LOCKED', 'USER_UNLOCKED',
                'ROLE_ASSIGNED', 'ROLE_REMOVED'))
            OR (target_type = 'PARTNER_ORGANIZATION' AND action IN (
                'ORGANIZATION_LOCKED', 'ORGANIZATION_UNLOCKED'))
            OR (target_type = 'BADGE' AND action IN (
                'BADGE_CREATED', 'BADGE_UPDATED', 'BADGE_AWARDS_SYNCHRONIZED'))
        ),
    CONSTRAINT ck_admin_audit_logs_reason
        CHECK (
            (action IN ('USER_LOCKED', 'USER_UNLOCKED',
                        'ORGANIZATION_LOCKED', 'ORGANIZATION_UNLOCKED')
                AND reason IS NOT NULL
                AND CHAR_LENGTH(BTRIM(reason)) BETWEEN 10 AND 500)
            OR (action NOT IN ('USER_LOCKED', 'USER_UNLOCKED',
                               'ORGANIZATION_LOCKED', 'ORGANIZATION_UNLOCKED')
                AND reason IS NULL)
        )
);

CREATE INDEX idx_admin_audit_logs_created
    ON admin_audit_logs (created_at DESC, audit_log_id DESC);

CREATE INDEX idx_admin_audit_logs_actor_created
    ON admin_audit_logs (actor_user_id, created_at DESC, audit_log_id DESC);

CREATE INDEX idx_admin_audit_logs_target_created
    ON admin_audit_logs (target_type, target_id, created_at DESC, audit_log_id DESC);

CREATE INDEX idx_admin_audit_logs_action_created
    ON admin_audit_logs (action, created_at DESC, audit_log_id DESC);
```

The migration backfills nothing. Earlier administrative changes were never recorded, so the log starts empty.

## 5. Append-only boundary

The application exposes no update or delete for `admin_audit_logs`, matching how the project already keeps
`attendance_adjustments` as append-only. No database trigger enforces this, because a trigger would also block test cleanup and
give no real protection against someone who controls the database account.

## 6. Transaction and concurrency boundary

- An administrative change and its audit row commit in one transaction. If the audit insert fails, both roll back.
- The audit writer requires an existing transaction, so a row cannot be written outside the change it records.
- Commands that can reduce the number of active Admins lock the active Admin `users` rows in `user_id` order before checking.
- Role, status and reset commands on one User lock that User's row first.
- Organization status commands lock the `partner_organizations` row first. A command blocked by `BR-117` reads the status under
  its existing Event root lock. A command already past that check when a lock commits finishes normally.
- Deleting a `user_roles` row removes only that role. No domain row refers to it.

## 7. Hibernate and application mapping

- `ddl-auto` stays `validate`. `User` maps `sessions_valid_from`, and a new `AdminAuditLog` entity in the `admin` feature maps the
  new table, with `details` mapped as JSON.
- The entity exposes no setter for an existing row.
- `V1` through `V18` are immutable.

## 8. Required database verification

- Clean migration through the new version, and upgrade from a V17 database with existing users.
- Existing `users` rows keep their data, and `sessions_valid_from` stays null.
- The database rejects: an unknown action, an action on the wrong target type, a lock with a missing, blank or too-short reason,
  a reason on an action that takes none, a non-object `details`, a non-positive `target_id`, a blank `target_label`, and an unknown
  actor.
- Deleting a User who appears as an actor is rejected.
- Hibernate validation passes.

## 9. Explicit physical exclusions

Sprint 11 adds no Permission or RolePermission table, no settings table, no lock-reason column on `users` or
`partner_organizations`, no second token table, no sign-in or read audit, no IP or device columns, no database trigger, and no
foreign key from `target_id`.
