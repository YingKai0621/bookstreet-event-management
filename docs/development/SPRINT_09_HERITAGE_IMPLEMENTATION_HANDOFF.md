## 3. Locked product decisions

- Organizer is the only Heritage management actor.
- Every verified Organizer manages the same shared Heritage collection.
- Admin has no Heritage management API or UI in Sprint 9.
- Heritage is permanently separate from General Feedback.
- Status values are exactly `DRAFT`, `PUBLISHED`, and `ARCHIVED`.
- Legal transitions are `DRAFT -> PUBLISHED`, `PUBLISHED -> ARCHIVED`, and
  `ARCHIVED -> PUBLISHED`.
- Anonymous public access returns only `PUBLISHED` content.
- `publicCode` is generated by the backend from title, canonical uppercase, unique, and immutable.
- Organizer mutations address the internal numeric identity.
- Public detail addresses `publicCode` at `/di-san/:publicCode`.
- Only a never-published `DRAFT` may be hard-deleted.
- First publish sets `publishedAt`.
- Archive and republish preserve the original `publishedAt`.
- Heritage QR is neither displayed nor persisted.
- Heritage text is stored and rendered as plain escaped text.
- Sprint 9 accepts only approved HTTP, HTTPS, or `/assets/heritage/` image references.
- Heritage has bounded local image upload, but no external asset library, public search API, category API,
  analytics, or production seed data.

Changing any item above requires documentation review before code changes.

Use the exact query parameters, DTO fields, validation limits, normalization, response shapes, status

concurrency token. Draft, archived, unknown, and malformed public codes use the same public-safe not-found
response.

## 10. Concurrency rules

Every Organizer update, lifecycle action, and delete requires the exact raw `updatedAt` last observed by
the client as `expectedUpdatedAt`.

- Guard the mutation with internal identity and matching `updated_at`.
- Guard lifecycle commands with the expected source status.
- Return `HERITAGE_STALE_WRITE` when a valid token no longer matches.
- Do not replay a stale mutation automatically.
- Every accepted mutation creates an `updatedAt` strictly later than the previous value.
- Normalize operation time to PostgreSQL microsecond precision.
- Do not depend on two system-clock reads being different.
- Preserve the raw timestamp string in the frontend rather than round-tripping it through browser `Date`.

Test strict advancement with a fixed or repeating Clock.

## 12. Security rules

- Keep Spring Security server-side Session authentication with the HttpOnly cookie.
- Do not introduce JWT, bearer tokens, refresh tokens, or `/auth/refresh`.
- Public Heritage GET routes are anonymous and read-only.
- Organizer routes require effective verified Organizer authority.
- An Admin-only account is denied.
- CSRF remains required for Organizer mutations.
- Heritage successes and errors use `Cache-Control: no-store`.
- Unknown JSON properties are rejected.
- Errors and logs must not expose SQL, constraint names, stack traces, credentials, Session values, CSRF
  values, or private content bodies.

Place the specific Organizer Heritage authorization rule before the existing broader Organizer matcher.
Keep security behavior outside the two Heritage route families unchanged.
